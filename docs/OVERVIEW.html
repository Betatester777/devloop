DevLoop — agentic software engineering workflow

A brief introduction to DevLoop — a proof-of-concept for agentic software engineering workflow with focus on sustainability, efficiency, and traceability.

🎯 What Is DevLoop?

DevLoop is an agentic software engineering workflow prototype that turns software delivery into a controlled, step-by-step process.


❌ Instead of…

  • 🎲 Writing all code at once and hoping it works
  • 📢 Manual handoffs between team members
  • 🐛 Discovering problems late in the process

✅ DevLoop provides…

  • 🧩 Manageable pieces tested against requirements
  • 📋 Automated, document-driven handoffs
  • 🛡️ Quality checks at every transition
🏭 Think of it as a software assembly line — each stage has a specialist, a defined handoff, and a quality check before the next stage can begin.

🔄 The Development Phases

Each feature moves through 7 fixed phases. The workflow only advances when the current phase has been completed and checked.

📖 What Happens in Each Phase

🔁 If testing finds a problem, the workflow returns to Build for correction — up to 3 times before a human is asked to step in.

🤖 The Team of Specialists

Eight AI specialists participate in the workflow. Each one has a clearly defined responsibility and produces a specific output.

💬 How Specialists Communicate

Specialists do not hand work to each other informally. They communicate through documents, and the Orchestrator checks those handoffs before work continues.

This document-driven approach creates a clear audit trail — every handoff is visible, checked, and recorded.

🛡️ Quality Gates

These are non-negotiable checkpoints that stop incomplete or low-quality work from moving to the next phase.

📌 Requirements Management

Requirements are the foundation of the workflow. Every planned task, test case, and code change must trace back to a specific requirement.

Two-level structure

  • Feature Groups — high-level capabilities
    e.g. "Card-based gameplay", "Score system"
  • Acceptance Criteria — specific, testable outcomes
    e.g. "Matched pairs stay revealed on the board"

Protective rules

  • Identifiers are assigned once, never reused
  • Retired items are marked, never deleted
  • Every criterion must have a task, a test, and a code change

⚙️ Two Operating Modes

Aspect👤 Normal Mode🤖 Fully Automated Mode
Requirements review👁️ Human confirms scope & priorities⚡ Auto-accepted
Architecture review👁️ Human reviews design⚡ Auto-accepted
Feature selection👆 Human chooses what to build next⚡ Automatic — next in queue
Review approval👁️ Human reviews each increment⚡ Auto-approved
Release🔲 Optional — human decides when📦 Mandatory after every feature
Version numbering✏️ Human chooses version🔢 Automatically incremented
Automated quality checks🛡️ Always enforced🛡️ Always enforced
🔑 Key point: Even in fully automated mode, quality checks are always enforced. Automation removes approval steps, but it does not remove verification.
